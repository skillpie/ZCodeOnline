# BUG修复（bugfix）

根据你描述的问题现象，自动分析代码库定位 bug 根因，**定位后无须确认直接修复**，并输出一份修复报告。

## 什么时候用

- 页面卡住、超时报错、数据对不上等功能缺陷，想直接修掉
- 有错误日志或堆栈，希望定位后一步到位修复
- 性能瓶颈定位清楚后，直接改代码

## 怎么用

直接用自然语言描述问题即可：

```
/bugfix 提交订单时页面卡住不动，等待 30 秒后超时报错
```

有日志或堆栈时一起贴上，定位更快、置信度更高；多个问题可一次提交：

```
/bugfix 订单创建报错，堆栈如下：<粘贴异常堆栈>
/bugfix 1. 提交订单超时 2. 库存数量与列表页显示不一致
```

## 修复流程

信息采集 → 信息不足追问（最多 2 轮）→ 确认后同步主分支代码 → 代码定位 → 自动修复 → 验证 → 输出报告

## 报告长什么样

每个 bug 一份 ≤ 12 行的精简报告：

```
[BUG-1] 提交订单超时 | 置信度：高 | 风险：高
根因：一句话说明
修改：文件:行号 → 改了什么
验证：编译/测试通过
遗留：无
```

置信度含义：**高** = 有日志/堆栈佐证，**中** = 代码推断，**低** = 推测。风险含义：**高** = 核心链路、影响面广或触发几率高，**中** = 部分影响或需特定条件触发，**低** = 边缘场景、影响小且触发几率低。

## 注意

- 尽量少打扰你：能在代码库自查的信息不会问；信息缺失时一次问完，最多追问 2 轮
- 同步主分支代码前会先征求你的同意，拒绝则基于本地代码分析
- 修复遵循最小改动原则，不顺手重构、不改无关代码
- 根因置信度为「低」时不会动手修，只给诊断结论建议人工介入
- 修复后自动编译/跑相关单测验证，验证失败会回退修改
