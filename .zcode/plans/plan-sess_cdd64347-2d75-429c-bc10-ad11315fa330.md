# 桌面版「远程控制」：输入远程码 → 整窗切换到远程机器

## 结论先行

复用现有 Web 隧道基建（relay 公网通道 + 16 位码即凭证 + daemon 持码），桌面作为**控制端**补三块：① daemon 控制链转发 assist 命令；② 隧道客户端共享层（从 web 抽到 client 包）；③ 桌面 renderer 隧道模式 + 复用远程控制弹窗。已确认：**整窗切换**语义 + **复用 Web 弹窗**。

## 数据流与状态所有者

```
桌面A renderer            桌面A main                relay(公网,已有)          机器B daemon(已有)
─────────────             ──────────                ──────────────           ─────────────────
弹窗(复用Web弹窗)
 │ getRemoteAssistCode ──IPC──► requestControl ────────(不经relay)────────► 控制socket
 │                              (desktopTunnelControl)                    tunnel.handle("assist-code")
 │ ◄── {code,expiresAt} ────────────────┐
 │ 输码/点「切换」= saveStoredAssistCode + location.reload()
 │ 重载bootstrap: localStorage有码 → DesktopTunnelRoot
 │ redeemAssistCode ──────IPC──► main fetch ── POST /relay/api/v1/assist/connect ──►
 │ ◄─ {hostId,connectToken,maskedPsk} ──┐          (CORS白名单不含桌面origin,
 │ connectTunnelServices                 │           故兑换必须走main; WS不受限)
 │ └─ renderer 直连 wss://relay/ws/tunnel/<hostId>（e2e加密,relay只见密文）──► 拼接管道 ──► B本地ws
 │ 远端services → Root 整窗=远端机器
 │ 断线→autoReconnect退避重连；码失效→清码+reload回本地模式
```

- 远程码权威所有者：被控端 daemon（不变）；存储码/机器列表：renderer localStorage（复用 `assistMachineStore`，不变）
- 隧道连接状态机所有者：新组件 `DesktopTunnelRoot`（桌面 renderer）
- 兑换 HTTP 请求所有者：desktop main（CORS 限制所致）

## 改动清单

### 1. packages/shared

- `src/channels.ts`：新增 IPC 通道 `GetRemoteAssistCode`、`RefreshRemoteAssistCode`、`RedeemAssistCode` 及 payload 类型映射
- `src/tunnel.ts`：新增 `relayWebOrigin(relayUrl)`（`wss://host/relay` → `https://host`）；web 包 `tunnelSession.ts` 的 `relayHttpOrigin` 一并收敛到这里

### 2. packages/client：隧道客户端共享层（从 web 抽入，web 改 import，避免双实现）

- `src/tunnel/transport.ts` ← web `tunnelSocket.ts` 整体迁入（`connectTunnelTransport/connectTunnelServices/TunnelConnectError/TunnelBootstrap`；无 DOM 依赖，`WebSocketImpl` 可注入，测试已支持）
- `src/tunnel/assistRedeem.ts` ← web `assistSession.ts` 的 `redeemAssistCode`（参数化兑换端点 URL：web 传相对 `/relay/...`，桌面传 main 代理通道）
- `src/tunnel/autoReconnect.ts` ← web 同名文件迁入
- `index.ts` 公开入口导出；web 包删除迁走文件、改从 `@zcode/client` 引入；对应测试随迁

### 3. packages/zcode-server-cli：daemon 控制链扩展（现仅回环 4950 端点可达 assist）

- `src/contracts.ts`：`controlRequestSchema` 加 `tunnel-assist-code` / `tunnel-assist-refresh`；`coreCommandSchema` 的 tunnel-control `action` 枚举加 `assist-code` / `assist-refresh`
- `src/supervisor/supervisor.ts`：`handleControl` 加两 case → 复用 `forwardTunnelControl`
- core 侧 tunnel-control 处理透传 `tunnel.handle(action)`（已支持，返回 `{status, pairingUrl: 码, expiresAt}`），映射为 `{code, expiresAt}` 形状
- 部署依赖：本机需 `./install_cli.sh` 重建 daemon，否则弹窗本机条目报错（弹窗已有 error 兜底）

### 4. packages/desktop

- `src/main/desktopTunnelControl.ts`：命令 union + 两 assist 命令；+2 IPC handler（daemon 不可达沿用 `unreachableStatus` 模式）
- main 新增 `RedeemAssistCode` IPC handler：Node fetch `${relayWebOrigin(DEFAULT_TUNNEL_RELAY_URL)}/relay/api/v1/assist/connect`，401/429 映射结构化错误码（invalid/rateLimited）
- `src/preload/index.ts` + window.zcode 类型：暴露 3 个新方法
- `src/renderer/src/desktopPlatform.ts`：实现平台契约 `getRemoteAssistCode`/`refreshRemoteAssistCode`（共享 `IPlatformService` 已声明的可选方法，实现后 Web 弹窗自动在桌面渲染）
- **新** `src/renderer/src/tunnel/DesktopTunnelRoot.tsx`：挂载读 `loadStoredAssistCode()` → 兑换 → `connectTunnelServices`（@zcode/client）→ 渲染 `Root`（远端 services；props 参照 web `TunnelAppRoot`：`allowRemoteWorkspace=false`、`suppressAccountOnboarding`、`suppressJwtInvalidReload`、`preferDirectoryBrowser`、`supportsEmbeddedBrowser=false`、`initialWorkspaceAbsPath=bootstrap.workspaces[0]`、`isDesktop`、`restoreSession=false`）；断线走 `createAutoReconnect` 退避；`AssistRedeemError(invalid)` → 清码 + reload 回本地模式；门禁卡片（连接中/失败重试/切回本机）
- `src/renderer/src/main.tsx`：主窗口 bootstrap 分支——localStorage 有存储码时跳过 databaseStartup/MessagePort 等待，直接渲染 `DesktopTunnelRoot`；无码走原本地流程

### 5. packages/ui：弹窗桌面适配

- `WorkspaceAssistCodeRefreshTrigger.tsx`：新增 `isDesktop` prop（Footer 已持有，透传）；分享链接 origin 桌面用 `relayWebOrigin(...)`、web 用 `window.location.origin`；桌面且存在活动存储码时 footer 加「切回本机」按钮（清码 + reload）
- i18n：`zh-CN.ts` / `en-US.ts` 补「切回本机」等文案（`assistCode.dialog.*` 前缀）

### 6. 测试与验证

- 迁移 web 隧道模块既有测试到 client；补 DesktopTunnelRoot 状态机与弹窗桌面分支的单测（node:test + tsx --test，以各包现有 test 脚本为准）
- 必跑：`pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed`、改动包的 test
- 手动验收清单：A 桌面输 B 的码→整窗切到 B；弹窗「切回本机」回本地；B 刷新码后 A 旧码失效自动回退；断网恢复自动重连；本机码复制/刷新（旧链接立即失效）

## 边界与风险

- 兑换走 main 进程是 CORS 硬约束（白名单仅 zcode.skillpie.cn 与 dev origin），不改 relay
- 隧道模式下 platform 仍是桌面 platform：`allowRemoteWorkspace=false` 阻断嵌套远程向导（与 web 一致）
- 隧道模式 `restoreSession=false`，远端会话持久化天然在远端 daemon，本地 tab 恢复不受污染
- update-status 等特殊窗口不受影响（分支仅主窗口 bootstrap）
