# 裸路径可下载：UI 自动转链接 + Agent 提示词双管齐下

## 目标

解决"Agent 回复里裸绝对路径不可点、拿不到文件"：UI 渲染时把正文裸路径自动改写成文件链接（数据/办公类点击即下载），同时在 Agent 提示词里引导交付文件用 markdown 链接输出。

## 第一部分：UI 自动转链接（治本兜底）

**新增 `packages/ui/src/lib/assistantFilePathLinks.ts`**（纯函数）：
`rewriteBareFilePathsToMarkdownLinks(content: string): string`

- **保护区间**（不改写）：`findMarkdownCodeRanges`（围栏代码块 + 行内代码，`assistantDirectiveParser.ts:214` 现成）、已有 markdown 链接和图片（`!?[…](…)`）、assistant 指令（`::zcode-file-citation{...}` 等）、`file://` 与 `https?://` URL 区间。
- **候选路径**（新正则，参考 shared `FILE_PATH_RE` 的中文标点边界写法但不限扩展名）：
  - 必须是"路径形"：`/` 开头（POSIX 绝对）、`X:\` 或 `X:/`（Windows 盘符）、`~/`、`./`、`../` 开头；
  - 以 `.` + 1~8 位字母数字扩展名结尾；**不含空格**（v1 保守，避开 CommonMark 目标地址空格问题）；
  - 前后边界用 FILE_PATH_RE 同款标点类（含中文标点），行号后缀 `:12:34` 不吞进链接；
  - 满足 Unicode 字符类，中文路径/文件名可用。
- **改写**：`[basename](path)`，basename 取最后一段。
- 应用条件：仅当存在 `onOpenFileLink || onOpenCodeViewer`（交互面）时执行；分享只读时间线等非交互面不动。

**接入 `message.tsx` MessageResponse**：在 citation 投影之后、现有 normalize 链之前插入该变换（约 :1378 的 `targetMarkdown` useMemo 内）。

**既有链路自动生效**：改写出的链接走 `resolveMarkdownFileLink`（绝对路径无需 workspacePath，`markdownFileLink.ts:311` 分支）→ MessageFileLink → 数据/办公类点击直接下载、右键打开/下载/复制路径。

**测试**：新增 `packages/ui/test/assistantFilePathLinks.test.ts`（模仿 `zcodeFileCitation.test.ts`）：中文路径、Windows 盘符、相对路径、csv/xlsx 命中、无扩展名/URL/代码块/已有链接/指令不命中、中文标点边界、行号后缀剥离、一行多路径。

## 第二部分：Agent 提示词引导（治标辅助）

1. **主 Agent**：`apps/zcode-cli/packages/core/src/context/dynamic-sections.ts` 的 `COMMUNICATION_PROMPTS.additional.beforeDefault`（:13 交付物句子之后）追加一条：
   > "When a turn produces deliverable files (exports, reports, documents, data files, archives), link each one in your final message as a markdown link — `[file.csv](/absolute/path/file.csv)` — instead of writing the bare path; clients render these as clickable download/preview actions."
2. **子代理**：`subagent/system-prompt.ts` `buildSubagentCommonNotes` :14 的 "share file paths (always absolute)" 句尾补充 "for files you produced as deliverables, use markdown links — `[name](absolute/path)`"。
3. **同步测试断言**：`packages/core/tests/subagent-explore.test.ts`（:74-80、:492-510）、`context-builder.test.ts`（:122-123 的 EXPECTED_COMMUNICATION_PROMPT）、`subagent-prompt-assembly.test.ts`（:247-260）。
