# 远程会话文件下载到本地（第一步：通用下载动作）

## 目标

给任意工作区文件加"下载到本地"能力，解决远程 Web 会话拿不到文件的问题（Excel/CSV 导出是首要场景）。不引入"产物识别"启发式——任何文件都可下载；产物聚合面留给第二步。

**两个入口：**

1. PreviewPane 头部新增独立下载图标按钮（窄视口自动隐藏防拥挤），「更多」菜单同步保留一项（手机端入口）。
2. 聊天消息里的文件链接（MessageFileLink）右键菜单加"下载"项；Write/Edit 工具块点击后也打开预览面板，天然被入口 1 覆盖。

**平台路径：** 桌面复用已有 `platform.saveFile`（系统保存框）；Web 新实现 `saveFile`（Blob + `<a download>` 浏览器下载）。

## 数据流（远程会话，所有者与事件顺序）

```
用户点「下载」（PreviewPane 按钮/菜单 或 文件链接右键菜单）
  → useWorkspaceFileDownload（唯一编排入口，packages/ui）
      以 workspacePath + workspaceIdentity + workspaceRemoteSessionId
      经 selectWorkspacePathFileService 选中正确的 fileService（远程会话指向远端执行机）
  → fileService.stat（远端执行机）→ 取 size；> 50MiB → toast 报错终止
  → readFileRange 循环（256KiB/次 RPC，远端→浏览器内存）→ 拼成单个 Uint8Array
  → platform.saveFile({ data, suggestedName })（作用于用户本地机）
      ├─ 桌面：现有 desktopSaveFile.ts 系统保存框写盘
      └─ Web：新增 webSaveFile → Blob + anchor 下载
  → toast：成功（桌面显示本地 path）/ 已开始（Web）/ 失败
```

无新增持久化状态；isDownloading 布尔态归 UI hook 所有，跟随现有 image-preview-dialog 惯例（无百分比进度）。

## 改动清单

**1. `packages/shared/src/platform.ts`**

- 导出纯函数 `sanitizeSuggestedFileName(name)`：取 basename、去路径分隔符/控制字符、≤120 字符——与 `desktopSaveFile.ts:190`、`pluginUiDownloadFile.ts:48` 规则一致。
- 更新 `saveFile` 的文档注释（`:683` 现写"普通 Web 端不实现"，已过时）：Web 以浏览器下载实现 data/sourceUrl 两个变体。

**2. `packages/web`（新增 `src/webSaveFile.ts` + 测试）**

- `createWebSaveFile(): SaveFileRequest → Promise<SaveFileResult>`：
  - `data` 变体：sanitize 文件名 → Blob → `URL.createObjectURL` + anchor 点击 → revoke；`URL.createObjectURL` 不存在（非浏览器环境）返回 `{success:false, error:"not_supported"}`；空 data 返回 `invalid_file_payload`（与桌面一致）。
  - `sourceUrl` 变体：anchor href 触发（与 image-preview-dialog 的 `startBrowserNativeDownload` 同语义）。
- 在 `main.tsx` `createWebPlatform`（:678 对象字面量，建议放 `openExternalFile` :834 附近）挂上 `saveFile: createWebSaveFile()`。

**3. `packages/ui`（新增 `src/lib/workspaceFileDownload.ts`）**

- 常量：`DOWNLOAD_CHUNK_BYTES = 256KiB`（与 PDF/pptx 习惯一致）、`MAX_DOWNLOAD_BYTES = 50MiB`（与桌面 `MAX_SAVE_FILE_BYTES` 一致）。
- `readWorkspaceFileBytes({ stat, readRange, maxBytes })`：可注入 readRange 的纯逻辑（照 `pptxPreviewData.ts` 的分块习语：循环读完拼一个 Uint8Array；size 超限抛带 code 的错误；并发截断防护）。
- `saveBytesToLocal(platform, bytes, fileName)`：有 `platform.saveFile` 走之（返回 canceled/saved/error），否则 Blob+anchor 浏览器下载兜底。
- 测试：`packages/ui/test/workspaceFileDownload.test.ts`（照 `pptxPreviewData.test.ts` 模式注入 fake readRange；覆盖分块拼接、超限、空文件、平台分支与兜底分支）。

**4. `packages/ui`（新增 `src/hooks/useWorkspaceFileDownload.ts`）**

- `useOptionalPlatform()` + workspace 作用域 fileService 解析（与 `WorkspaceShellLayout.tsx:1641` 同源）。
- 暴露 `downloadFile({ path, suggestedName?, workspacePath, workspaceIdentity, workspaceRemoteSessionId })` 与 `isDownloading`；内部 toast：下载开始 / 成功（桌面含 path）/ 失败 / 文件过大。
- i18n 文案 id 用 `workspaceFile.download*` 前缀。

**5. `packages/ui/src/PreviewPane.tsx`**

- 头部 actions 区（:1638）加下载图标按钮（Download 图标，DESIGN.md 方形 icon button 规格）；窄视口（isMobileCompactViewport 或等价条件，随现有头部减法规则）隐藏。
- 「更多」菜单（:1727–1831）加"下载到本地"菜单项，放在复制路径项附近；条件 `source.path && !isEditingFile`，下载中 disabled。

**6. `packages/ui/src/components/ai-elements/message.tsx`**

- MessageFileLink 右键 ContextMenu（:1206–1255）加"下载"项（目录链接不显示；hook 内会重新 stat 校验，与 openInEditor 前重新 stat 的既有防线一致）。

**7. i18n：`packages/ui/src/i18n/locales/zh-CN.ts` 与 `en-US.ts`** 同步新增 `workspaceFile.download / downloadStarted / downloadSucceeded / downloadFailed / fileTooLarge`。

## 测试与验证

- 新增：`packages/ui/test/workspaceFileDownload.test.ts`、`packages/web/test/webSaveFile.test.ts`。
- 必跑并如实报告：`pnpm typecheck`、`pnpm lint`、`pnpm test:unit <新测试文件>`。
- 手动验证清单：桌面系统保存框；Web 本地会话 Blob 下载；Web 远程会话取远端文件（核心场景）；xlsx 二进制完整性（下载后能打开）；中文名文件；空文件；>50MiB 报错。
- E2E：浏览器下载断言在现有 harness 下成本高，本次以单测 + 手动清单覆盖，E2E 场景记为后续项。

## 已知副作用（有意接受）

- `buildPluginUiHostCapabilities.ts:17` 的"平台有 saveFile（桌面）才声明 downloadFile"门在 Web 上将自动放行——Web 确实具备下载能力，语义一致；如需保持桌面限定需另加门，默认不做。
- image-preview-dialog 在 Web 上从"fetch + 手动 anchor"改走 web saveFile，行为不变、路径归一。

## 不做（第二步，另行规划）

产物聚合面（Gen-UI 式交付目录约定 + 会话内产物卡）、下载百分比进度、PreviewPane 之外文件树的批量下载。
