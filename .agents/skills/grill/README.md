# Grill - 灵魂拷问

> 方案写好了？先别急着动手——让 AI 帮你「拷问」一遍。

Grill 会对你提出的技术方案或架构设计进行穷追猛打式的追问，每次只问一个问题，并附上它推荐的方案，直到双方达成共享理解。

## 为什么需要它？

写方案时，我们容易忽略边界条件、权衡取舍和隐含假设。Grill 扮演「严格的技术评审者」，帮你提前发现：

- 设计中的盲区和未覆盖的边界场景
- 决策之间的依赖和冲突
- 被默认接受但未经论证的假设

## 使用方式

直接输入 `/grill`，然后描述你的方案或设计即可。

```
/grill 我们计划把订单服务从单体中拆分出来，用 Kafka 做异步消息通知
```

## 两种模式

| 模式         | 说明                                       | 触发方式           |
| ------------ | ------------------------------------------ | ------------------ |
| **普通模式** | 只拷问，不生成文档                         | 默认               |
| **文档模式** | 拷问的同时生成 ADR（架构决策记录）和术语表 | 明确说「生成文档」 |

## 工作原理

1. **逐一追问** — 每次只问一个问题，等你回答后再继续，不会一次抛出十个问题让你抓狂
2. **附带推荐** — 每个问题都带上 AI 推荐的答案及理由，供你参考
3. **先查代码** — 能通过代码库自行回答的问题，不会反过来问你
4. **不动手** — 在你说「达成共识」之前，绝不会开始实施

## 适用场景

- 技术方案的评审前压力测试
- 架构设计决策的推敲与论证
- 新需求的可行性讨论
- 任何你想在动手之前把方案想清楚的场景
